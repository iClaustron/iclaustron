# ic_capi — module notes

The C ABI of iClaustron, built as `libiclaustron` (shared and static),
with its header `include/iclaustron/ic_apid.h` generated by cbindgen
from `src/lib.rs` (`cargo xtask header` checks the checked-in copy).
The design is chapter 04, "The C ABI".

## Source files

| File | What it is |
|---|---|
| `src/lib.rs` | every exported `ic_*` function, the C values and types |
| `build.rs` | the shared library's soname (Linux) and install name (macOS) |
| `cbindgen.toml` | how the header is generated: the C names of the types |
| `iclaustron.pc.in` | the pkg-config file `cargo xtask install` fills in |
| `tests/c_api.rs` | the `c_api` integration group, against a live cluster |

The C code had no counterpart: its header was the API itself, with the
`_OPS` function tables of `ic_apid.h`. Nothing is translated from
`legacy-c/`.

## How a call crosses

- A handle is a pointer to the Rust object itself, cast to an opaque C
  type: `IC_APID_CONNECTION*` is the `ApidConnection` the box holds, so
  that a callback is handed the very connection it runs on. A table or
  index handle holds the description with its names as C strings,
  made once at bind.
- Queries and transactions cross as their `u32` ids; a stale id finds
  nothing, since an id carries its slot's generation.
- Every entry is wrapped in `catch_unwind`; a panic in a call on a
  connection marks it unusable (`ApidConnection::set_unusable`), and
  every later call on it but the free returns `IC_ERROR_INTERNAL_PANIC`.
- A C callback is called through one trampoline, which Rust sees as the
  query's callback; the C function is kept in the query's binding word
  (`ReadKeyArgs::binding`) and turned back into a function pointer
  there.
- An executor, its submitters, shapes and requests are boxes of the Rust
  objects too (`Executor`, `Submitter`, `Arc<OpShape>`, `Request`). A
  request owns its operations' rows, and its handle stays the same box
  while `ic_apid_submitter_execute` moves the request to the executor
  and back, so the row pointers C holds stay valid across runs.

## Deviations from the C code

The Phase 0 header was written by hand before the code; the generated
one follows what was built (chapter 04, rewritten 2026-10-14): ids in
place of query and transaction objects, rows owned by the query (Q10),
no `cluster_id`, no joinable transactions, no `_OPS` tables, no WHERE
conditions or scans in 0.1.
