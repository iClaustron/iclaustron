Data model · built

Everything a transaction needs lives in one thread

Shared: ApidGlobal

NodeShared per node: published state (atomics), membership word (CAS), and the Sender: waiting and spare buffers, writer flag, adaptive send. Thread table, send pool, dictionary cache.

Per thread: ApidConnection

Inbox, queries and transactions in generational maps, TC records with free lists, the active vector, per-node staged and outgoing buffers, executed list.

ApidQuery and Transaction

A query owns its key and attribute rows: no pointer into application memory, no unsafe. A transaction is local until its first send.

Query: Idle → Defined → Sent → Completed → Idle · no allocation per transaction once warm

Only two things cross threads: requests appended to a node's send buffer, and replies coming back in a signal page. Everything else, queries, transactions, coordinator records, is owned by one ApidConnection and needs no lock. Query lists and TC records are reused; inline buffers spill to the heap rather than refuse.
