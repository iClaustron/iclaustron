One wait point, one loop

fn submit(&self, r: Request) {
  let wake = {
    let mut ib = self.inbox.lock();
    ib.requests.push(r);
    take(&mut ib.waiting)
  };
  if wake { self.cond.signal(); }
}

Same shape as a receive thread's post: append under a short lock, wake only if asleep.

Replies before requests: they free records and room in the pipeline.

Batching comes on its own: all requests admitted in one pass share one write per node.

Back-pressure twice: a bounded request list, and an in-flight limit.

Submit is the same code shape as a receive thread's post. Exchange, which already swaps emptied pages for posted ones, would also swap out the request list, so one lock takes everything. Under light load a request goes out alone. Under heavy load many callers' requests share each socket write, and the per-batch costs spread. Node failures fail the affected requests with their error. A deadline can be checked at admission.
