What keeps it fast

A node's state has one writer

The receive thread that owns a node executes its heartbeat replies. Everyone else reads atomics; no mutex.

One lock per inbox per round

Signals are sorted per thread with no lock held, then posted as one page under one short lock.

Wake a thread only if it sleeps

A waiting flag under the inbox mutex: posting to a busy thread costs no system call.

The thread that sends does the write

Append to the node's send buffer; if no one is writing to that node, take the buffer and write it outside the mutex. Later signals go to the pool.

Four rules. The first removes the C code's three-mutex node failure path. The second and third keep the receive thread's cost per round, not per signal. The fourth gives one socket write per node per send without anyone writing in a loop for others. Failure checks also cost one atomic load per poll, through a link-event counter.
