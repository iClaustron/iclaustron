Threading

One rule shapes everything

Receive threads receive and route.
User threads execute.

The C++ NDB API decodes every signal on its receive thread, which becomes the bottleneck with many threads. Here a receive thread does one lookup and one copy per signal; decoding, state and callbacks run on the thread that owns the query.

The deliberate difference from the C++ NDB API. Their receive thread executes the signal then wakes the user thread. Ours only looks at the block number and copies the signal into that thread's page. All real work scales with the application's own threads.
